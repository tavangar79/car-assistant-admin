# car-assistant-admin — Car Assistant admin panel

## Communication style
- Keep answers short and simple. Answer first, with no preamble or recap.
- Elaborate only when asked.
- Always flag risky or destructive actions in one line.
- **Never commit or push.** The CTO root delegates work here and decides when to commit. Leave changes
  uncommitted and report the diff.

A browser panel for one operator: dashboard, users (block/unblock, profile edit, read-only record tabs) and
the service catalog as a global → make → model → trim tree. It's a standalone repo, used as the `admin/` submodule of the car-assistant manager repo.
The API contract lives at the root: `API-ADMIN.md` (and `API-PHASE7.md` for the catalog).
**Mobin** (`mobin` agent, `.claude/agents/mobin.md`) owns work here.

## Stack
- Vite 8 + React 19 + TypeScript 6 (strict, `noUncheckedIndexedAccess`)
- Tailwind CSS v4 + shadcn/ui (Radix, "nova" preset, slate + indigo tokens in `src/index.css`, Vazirmatn font, RTL-ready logical classes), light + dark themes
- React Router 7 (data router), TanStack Query 5, zod 4, Recharts 3 via shadcn `chart`, lucide icons, sonner toasts
- Vitest 5 + Testing Library + MSW 3, ESLint 10 (typescript-eslint, react-hooks), Prettier

> TypeScript stays on 6.0: typescript-eslint supports `<6.1`. Don't bump to 7 until it does.

## Folder layout
```
src/
  main.tsx               browser router + providers + connectSession
  app/                   routes, layout (sidebar + top bar), providers, query client, 404
  components/            shared app components (states, copy-id, value-cell, page-header, theme)
  components/ui/         generated by the shadcn CLI; edit only when needed
  features/<name>/       api.ts (zod schemas + calls + query hooks), pages, components, colocated tests
    auth/                login page, AuthGuard (GET /auth/me), session (401 → /login?next=…&expired=1)
    catalog/             scope tree (global → make → model → trim, search, per-node row counts) with the
                         selected scope in the URL; tabs for service items + interval defaults showing own,
                         override and inherited rows (resolution in tree.ts, pure + tested); add/override/edit
    users/               list, detail, edit profile, block/unblock; record tabs read GET /collections/:name
                         (records-api.ts) into a generic table from `fields`, cursor paging
    dashboard/           totals + time series, range presets (pure, tested)
  hooks/                 small shared hooks
  i18n/                  en.ts (every UI string) + t()
  lib/                   api-client, token storage, formatters, shared zod pieces
  test/                  setup, MSW server + handlers, fixtures, renderApp()
```

## Conventions
- **Feature folders.** Each feature's `api.ts` holds its zod schemas (mirroring the contract exactly), the fetch
  calls and the TanStack Query hooks. Pages and components sit next to it.
- **api-client.** Every call goes through `apiRequest(path, schema, options)` / `apiSend` in `src/lib/api-client.ts`.
  It adds the base URL + `/api/admin`, the Bearer token, parses `{ error: { message, details? } }` into `ApiError`,
  validates the body with zod (drift fails loudly as `invalid_response`), and on a 401 clears the token and
  redirects to `/login?next=…&expired=1`. Map errors to UI text with `errorMessageKey(error)` (status/kind only,
  never the message text).
- **i18n.** No string literals in JSX: use `t('key', params?)` from `@/i18n`. Add keys to `src/i18n/en.ts`.
  Format numbers and dates with `src/lib/format.ts` (`Intl`, Tehran time), so Persian can be added later.
- **Logical CSS classes** only: `ms-/me-/ps-/pe-/start-/end-/text-start/text-end`. Cells and inputs that hold
  user text get `dir="auto"`.
- **No Stitch** for this repo: UI is built from shadcn/ui components. Clean and calm: slate neutrals with an indigo primary (tokens only, no raw colours), clear spacing.
- Every list, chart and detail view has loading, empty and error states (`src/components/states.tsx`).
- Destructive or blocking actions go behind a confirm dialog that names the target.
- Tests: pure helpers get unit tests; flows get Testing Library + MSW tests through `renderApp(path)`.
  MSW handlers follow the contract exactly (`src/test/server.ts`, `src/test/fixtures.ts`).
- Simple and readable beats clever. No packages or abstractions beyond the task.
- **Never run git write commands** (add, commit, checkout, stash, reset, push…). Read-only git is fine.
